# Google Earth / Geospatial Scale Rendering Research Notes

Date: 2026-09-28

Purpose: extract general rendering/streaming principles useful for The Advisor Game. This is a design reference, not a dependency on Google services or Google map data.

## Observed / documented patterns worth adopting

1. **Canonical location is independent from zoom.** Google Maps documents world coordinates separately from pixel/tile coordinates; pixel resolution increases with zoom while the represented location remains the same.
2. **Hierarchical spatial refinement.** 3D Tiles organizes renderable content in a spatial tree with progressively lower geometric error in child tiles.
3. **Screen-space error (SSE).** Finer children are selected when the error of a coarser representation would become visible in screen pixels. The metric depends on world-space error plus view distance/projection and screen resolution.
4. **Parent-to-child refinement.** Replacement refinement keeps the same spatial coverage while substituting a more detailed child representation; additive refinement is available for layers that are genuinely additive.
5. **Viewport-bounded streaming.** High-detail content is requested as the viewer explores instead of fully materializing the world.
6. **Semantic map styles/layers.** Google Earth exposes different information-density modes (imagery-only through progressively richer borders, labels, roads, landmarks and other POIs). The lesson for our game is explicit scale/importance policy rather than all semantic classes being visible at once.
7. **Performance-quality tradeoff is explicit.** Terrain/detail quality can be reduced for performance; our equivalent must stay bounded while preserving canonical identity.

## Application to The Advisor Game

- Campaign SEED + canonical coordinates remain the only fixed world authority.
- The canonical scale UI remains: 1/10, 1/20, 1/50, 1/100, 1/250, 1/500, 1/1000, 1/2500, 1/5000, 1/10000.
- Internally, visible spatial cells refine hierarchically according to projected error and physical footprint.
- A finer LOD must be a refinement of the same parent world area, never a new camera-relative world.
- A parent/previous ready representation stays visible until all replacement coverage needed for the viewport is ready.
- Labels, borders, roads, settlement classes and landmarks use explicit physical-scale eligibility plus deterministic importance/decluttering.
- Settlement existence/coordinates are not generated by LOD. A single SEED-only settlement hierarchy is reused at every scale.
- Cache eviction removes only presentation resources; revisiting the same cell must regenerate identical canonical content.
- At ~10 km local views, underlying city/town/village spacing must be physically coherent, and semantic display must not present every minor place as a city-class label.
- Use bounded overscan and motion-direction prefetch to prevent navigation holes without unbounded world loading.
